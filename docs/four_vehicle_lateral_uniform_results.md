# 四车统一策略优化实测记录

本记录对应 MATLAB R2023a 于2026-11-10至11-11的实际执行。当前场景四车独立重复搜索3次均通过，搜索总耗时中位数 **8.7881438 s**，最大8.8257847 s，达到当前场景≤60 s的目标。首批确认的6个场景全部成功，36个车辆对检查全部通过；航向整体增加0.2 rad的场景耗时64.7916579 s，仍存在耗时敏感性，不能宣称所有场景均在60 s内。

本记录的正常基准时间包括四次搜索调用内部的安全验收和逐车独立验收，不包括共享占用写入、最后六车对审计、绘图、动画及文件导出。完整六车对验收仍是结果有效的必要条件。独立横向开关诊断的计时仅包含核心搜索调用，不能与这里的时间直接混算。

## 收益归因与被否决的实验

最终优先采用公共Dubins权重8及首个合法连接返回，从搜索规模上减少后续积分和碰撞工作；精确重复剖面去重和本次动作末端状态复用属于已保留的局部优化。多相位分支显式关闭保证公共配置明确，并未在本轮单独测得该项收益。

同一权重8策略关闭动态减速剪枝，独立运行3次得到10.0578044、9.3658083、9.4320314 s，中位数9.4320314 s；启用后中位数8.7881438 s，减少约6.83%，约1.073倍。两组返回路径和扩展/生成节点相同。启用时每车跳过更快动作数为0、74、38、486，合计598；关闭动态剪枝时仍保留原静态减速剪枝，因此003仍记录4次跳过。这说明减少了候选检查，但幅度小于1.2倍阈值，当前样本不足以证明稳定的独立加速收益。

关闭动态剪枝的证据目录：`outputs/four_vehicle_lateral_uniform/benchmark_20261111_000222_790_tp6aa4794c_7cb3_4ae0_8fe7_7c7856d8348f/`。

减速剪枝仅作用于同一父节点、同一挡位、同一转角下后续更快控制；独立转向继续检查，所有被接受的动作仍执行运动学、横向、静态、动态矩形和资源检查。移动障碍可能使减速动作碰撞而更快动作可行，因此这是用户授权的启发式剪枝，可能漏掉可行解。测试保留了这个反例。

曾将剪枝扩大为减速动作任何碰撞均触发，当前场景反而耗时36.183 s，004扩展节点由89增至1632；该方案已否决，最终保留中间碰撞触发规则。公共权重3配合剪枝的另一诊断中，002约60.059 s触发单车预算；该记录是预算内未找到解，不能称为数学无解。以上实验不能与权重8收益合并归因为“剪枝加速”。

## 横向限制开关诊断

`benchmark_lateral_constraint_overhead(3)`使用完全相同的场景、四车顺序、公共策略及车辆参数，每次分别从零新建搜索和时空地图，只切换`lateral_acceleration_constraint_enabled`。诊断计时只含核心搜索调用；每组路径在计时外都按4.9 m/s²独立验收。关闭限制所得路径不属于合格规划结果，不执行最终6车对验收。

三次启用结果均完成四车且均通过4.9 m/s²验收，核心搜索时间分别为8.735899、8.680944、8.945972 s。关闭限制的三次运行均在vehicle_003的每车60 s预算内超时，未完成四车：前三车均找到路径，但横向峰值分别为15.392111、6.545455、16.348416 m/s²；003搜索尝试约60 s后峰值仍超过限制。因此这组实验说明不受限搜索会改变路线并可能在同一预算内失败，不能把两组总耗时解释成横向约束计算本身的开销差值。

完整逐车数据、严格独立横向报告和配置快照位于`outputs/four_vehicle_lateral_uniform/lateral_ablation_20261111_000456_826_tp979e6a57_fe6d_4896_9dc8_8d7ea39886f5/`。其中结果MAT与摘要均标明`diagnostic_only`；不得将关闭约束的结果用作控制轨迹。

## 与历史Day7及方案C的关系

`outputs/day7_plan_c/day7_plan_c_result.json`中实际记录：原Day7搜索17.8168712 s，加方案C末段剖面1.2709658 s，总计19.087837 s。原搜索逐车耗时为0.7515141、10.3279401、4.1411286、2.5962884 s，来自名称保留拼写的 `outputs/day7_four_vehicle/day7_vehicle_ttiming.csv`。

`run_day7_plan_c_experiment`读取已保存四车MAT，只从002既有t=4 s节点调用终点连接器，保留其他三车及原路线；因此方案C这次调用并没有重新从零搜索四车。其19.09 s包含历史四车搜索时间和本次末段剖面时间，是性能参考，不能作为当前横向约束开关的严格对照。

前后代码还存在局部弯道限速包络、可行动作集合、起步等待策略、连接返回策略、启发式配置和搜索轨迹变化。横向约束会改变后车所见的动态占用，从而进一步改变搜索规模。原Day7还含按车辆配置的启发式和精修设置；最终版本已改成四车公共策略。故不能把19.09 s与528.80 s的差值全部归因于新增横向计算函数。严格的开关对照使用 `benchmark_lateral_constraint_overhead`，结果需按其独立计时范围解读，关闭约束的轨迹仅作诊断。
